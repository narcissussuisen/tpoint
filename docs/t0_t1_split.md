# T+0 / T+1 算法拆分说明（v9.4.0 · 2026-08-04）

## 拆分结构

```
core/miji_alpha.py     信号生成（单一信号源，两模式共用 —— 铁律：同源不分叉）
core/settle_rules.py   结算制度规则模块（新增，本拆分的核心）
core/monitor.py        推送链集成点：_risk_gate 后 → settle_rules.filter_signals（开关默认关）
```

两类算法「各自维护」的边界：**信号因子/参数演进共源同改；结算/频率/成交规则差异全部收敛到 settle_rules.py 单文件**，改 T1 规则不碰 T0，反之亦然。

## 标的归类

| 模式 | 标的 | 判定规则 |
|---|---|---|
| T+0 | 161129.SZ 原油LOF易方达、513310.SH 中韩半导体ETF华泰柏瑞 | 代码 1xx/5xx（LOF/ETF）自动判定；monitor_config per-symbol `settle_mode` 可覆盖 |

## 三类差异的处理口径

| 维度 | T+0（LOF/ETF） | T+1（A股个股） |
|---|---|---|
| **信号生成** | 共用 miji_alpha 信号源，闸门全量放行（MAX_B/S_DAILY=12、COLDOWN_BARS=3 现状不变） | 共用同一信号源；结算闸门按下方频率规则过滤后才推送 |
| **调仓频率** | 当日可多次往返（买→卖、卖→回补均不限次数） | **每方向每日至多 1 次完整往返**：B启动（正T）与 S启动（反T）各一次；持仓 trip 未闭合时同向信号忽略；X 仅在持仓 trip 中放行 |
| **成交规则** | 信号即成交，当日买可当日卖，无底仓前提；成本无印花税（cost_for_symbol 已区分） | 做T依托底仓：正T=先加仓买→卖出的是底仓；反T=先减底仓→当日回补。监控层不掌握真实底仓，以「每方向一次往返」近似约束频率；底仓规模属用户侧管理；成本含印花税（卖边万5.641） |

## T1 闸门状态机（settle_rules.filter_signals）

- 空仓态：B → 开正T trip（若当日 B 向次数未用完）；S → 开反T trip（同理）；X → 丢弃
- 正T 持仓中：S/X → 闭合（计 B 向完成 1 次）；B → 忽略
- 反T 待回补中：B → 闭合（计 S 向完成 1 次）；S/X → 忽略
- 状态存 state.json（`_trip_open_{sym}` / `_t1_done_{B|S}_{sym}_{ymd}`），跨重启持久化

## 开关与回滚

- 开关：`data/monitor_config.json` 顶层 `"_global": {"settle_split_enable": true}`（**默认关闭**，关闭时生产行为与 v9.3.1 完全一致）
- 回滚：开关置 false 即恢复；热重载（每轮读配置），无需重启进程
- 验证记录：T1 [S,S,B,B,S]→[S,B,B,S]（反T+正T各一次）；T0 原样放行；开关关闭完全不介入（2026-08-04 单测通过）
