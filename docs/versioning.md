# tpoint 版本规则（versioning.md）v1.0

> 2026-08-26 建立。此前 memory 长期引用本文但文件缺失，导致 P6-P12 连续 bump 产生版本通胀。
> 本文为**版本号治理的唯一权威真源**，所有 VERSION 变更必须对照本文判定。

---

## 0. 三轨版本体系（互不干扰）

| 轨道 | 载体 | 代表 | 谁 bump |
|---|---|---|---|
| **生产核心** | `VERSION` 文件 | `10.10.0` | 仅当 **monitor 实盘实际消费**的代码/配置变更 |
| **研究线** | 策略层名（不入 VERSION） | `GT-TB v1.1` | 研究脚本/模型版本，**永不写 VERSION** |
| **方法论** | `METHODOLOGY_VERSION` 文件 | `1.1.0` | 方法论文档结构性/量化定义变更 |

**硬规则**：
- 研究态改动（回测脚本、ML 模型训练、验证报告）**禁止 bump `VERSION`**（2026-08-26 教训：P9 顶底 ML 为研究态却把 VERSION 提到 10.8.0，属错误 bump）。
- 数据基础设施（tick 管道等）仅当 monitor 开始消费时才 bump。

## 1. 生产核心版本号语义（MAJOR.MINOR.PATCH）

| 段位 | 触发条件 | 示例 |
|---|---|---|
| **MAJOR** | 信号语义/出场体系结构性变化（如同步双向、结算制度拆分、出场源体系重构） | v9→v10（量能确认+watchlist 重构）、未来 11.0.0 |
| **MINOR** | 新功能旋钮（monitor 可热重载的新开关/新配置项）、新数据源接入生产 | 10.5.0→10.6.0（标签解耦）、10.9.0→10.10.0（FIXSTOP 旋钮） |
| **PATCH** | 修复类改动（不改信号语义/出场行为） | 10.1.1→10.1.2（首扫抑制边界） |

**MINOR 通胀防扩散守则**：
- 同一天多个 MINOR 必须**合并为一次 bump**（除非跨多个 release 窗口）；
- 展示层改动（如卡片标签）若无行为影响，应降为 PATCH 或并入其它 bump；
- **禁止为研究阶段单独 bump**（研究线版本走 GT-TB 自版本）。

## 4. 版本号进位策略（防"10.10.0"式歧义）

- MINOR 递增到 9 后，**优先考虑是否已达 MAJOR 门槛**（信号语义变化）→ 是则进 MAJOR（11.0.0）；
- 若确属纯功能旋钮且 MINOR 已到 9，允许 10.10.0 写法（语义=10 代第 10 个功能版），但必须在 CHANGELOG 显著标注；
- **任何 bump 必须写 CHANGELOG**（含"生产/研究/基建"轨道标注），禁止裸 bump。

## 5. loop_engine 阶段与版本对应

| loop 阶段 | 性质 | VERSION 影响 |
|---|---|---|
| P6 标签解耦 | 生产展示层 | 可 bump（MINOR）或并入 |
| P7 参数验证 | 研究 | **不 bump** |
| P8 tick 管道 | 基建 | monitor 消费前不 bump |
| P9 ML | 研究 | **不 bump** |
| P10 全栈验证 | 研究 | **不 bump**（GT-TB 名义） |
| P11 GT-TB v1.1 | 研究 | **不 bump** |
| P12 出场配置 | 生产旋钮 | bump（MINOR）|

**守门（已实现，2026-08-26）**：loop_engine stage 的 bump 动作前必须调用 `core.guard_bump(stage)`；
`core.PROD_CONSUMED_STAGES` 白名单之外（研究/基建）的 stage 一律拦截 bump 并记录告警。
当前白名单：`{'p6_exit_label', 'p12_exit_config'}`。
