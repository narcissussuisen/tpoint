一、出场提醒信号使用说明

1. 触发条件（生产配置）

出场由 EXIT_CFG 控制，当前生产值：

make_config(use_stop=False, use_time=False, use_trailing=True, trail_activate_pct=0.4, trail_pct=0.6, s_signal_exit=True)

2. 使用规则与优先级

  • 同一根 bar 内优先级：硬止损 > 反向信号(S/B) > 移动止损 > 时间止损。生产实际只走 反向信号 → 移动止损 顺序（前两者关闭）。
  • 持仓全程持续监控（任务四）：不限制每日仅一次完整买卖周期；以 bar 索引冷却（COLDOWN_BARS=3）放行所有有效波动点。
  • 平仓后 pos=None 持久化 → 配对完成后不会重复推送该笔出场。

3. 不同市场环境的适用场景

  • 震荡 / 均值回归市：反向信号出场 + 移动止损保护浮盈最有用——这正是做 T 的本质（吃波动）。
  • 单边趋势市：移动止损能锁利，但反向信号可能过早平掉顺势仓；此时应配合降低反向信号权重（当前引擎未做此调节）。
  • 涨停 / 跌停极端市：涨停 regime 抑制反 T 开空（A2 保护，见下），但出场不受限；一字板平盘时 macd 严格化(v9.1.4) 已防虚假信号。

4. 出场与入场如何配合

  • B 开多 / S 开空 是入场；对应反向信号 S 平多 / B 回补 是出场。
  • 正向 T = 先 B 后 S 配对；反向 T = 先 S(开空) 后 B(回补)。
  • 当前自由双向（任务三）：可同侧累加（加仓）、可反向平仓，不再强制 B/S 严格交替。

5. 是否需结合大盘走势确认？

当前不需要、也不读取大盘。出场纯由个股价格结构（VWAP / ATR / MACD）决定。 大盘 / 品类确认逻辑仅存在于冻结分支 exp/index-gating（commit a708c53 等，含 5m 指数门控），从未合并到 main，生产不生效。

二、仓位管理判断标准（量化）

单笔仓位推导：strength_size(g_dev_pct, m_present)

strong = (|价格−VWAP|/VWAP ≥ 2.0%) or bool(m_present) → 返回 4成，否则 2成。

其中 m_present = 'MACD' in 信号依据。生产 REQUIRE_MACD=True ⇒ 每个 B/S 必含 MACD ⇒ 常态恒为 4成；早盘 i<LOCAL_W(=15) 降级为 gravity-only（无 MACD）⇒ 2成（除非 |dev|≥2%）。

常态 (i≥15)B / S是（强制）任意4成

累计与上限

  • 单标的累计上限 MAX_SIZE_PCT = 8（成 = 80%）。
  • 每日次数上限 MAX_B_DAILY = MAX_S_DAILY = 12。
  • 同向累加：add = min(信号仓位, 8 − 已持仓位)，加权均价更新。
  • 反向平仓：min(信号仓位, 已持仓位)。
关键澄清：代码没有「因子数 → 仓位」的阶梯规则。 共振因子数量不改变单笔仓位；且生产 VOL_DIV_ENABLED=False（量价背离禁用，样本净负），只剩引力 + MACD 两因子，三因子完全共振在生产中不可能发生。

逐条回答

① 三指标完全共振时，最大仓位上限是多少？

  • 单笔仍是 4成（MACD present 恒真）。真正上限是累计 MAX_SIZE_PCT = 8成(80%)——无论几因子，单标的当天最多堆到 8成。
  • 若未来启用 VOL_DIV 恢复三因子，单笔依旧 4成，瓶颈仍在 8成累计。

② 两指标共振时，如何结合大盘趋势及相关品类表现推算仓位？

坦诚：当前完全没有。仓位只由「VWAP 偏离幅度 + 是否含 MACD 背离」决定，不读指数、不看板块、不参考相关品类。 大盘 / 品类门控仅存在于冻结分支 exp/index-gating，未落地。 即「两指标共振 + 大盘推算仓位」是尚未实现的预期设计，不是既有规则。
可落地方案（需你确认）：引入指数（如 399006 创业板指 / 000001 上证）当日涨跌或 5m 趋势作为仓位系数——例：大盘向下超阈值时，即便两因子共振也降为 2成；大盘向上配合时维持 4成。

③ 卖出信号的仓位调整规则是否与买入对称？

  • 幅度完全对称：B / S 走同一 strength_size，同样 4/2成 规则，同累加上限 8成，同反向平仓 min(信号仓位, 已持仓位)。
  • 唯一不对称在「开仓门控」：卖出（开空 / 反 T）有涨停 regime 抑制（not near_limit_up，A2 保护）——当日最高涨幅触涨停阈值（主板10% / 创业板·科创板20% / 北交所30%）时不开新空；买入无此门控。即极端涨停行情压制反 T、正 T 不受限。
  • 出场标签不对称是语义性的（S=平多·红 / B=回补·绿），非仓位幅度不对称。
一句话总结：出场 = 移动止损 + 反向信号两类（硬止损/时间止损关），纯个股价格结构驱动、不读大盘； 仓位 = 单笔 4成(常态)/2成(早盘)、单标的累计≤8成；卖买幅度对称，仅反 T 开空受涨停 regime 抑制； 「因子数→仓位」阶梯与「大盘/品类门控」当前均未实现（前者非设计、后者冻结未合并）。

三、量价背离（vol_div）为何被禁用？顶 / 底背离分别说明

先正名：顶背离与底背离在代码里是「同一个因子」vol_div，不是两个独立开关。 禁用是因子级一刀切（VOL_DIV_ENABLED=False，见 core/miji_alpha.py:23），即顶、底一起关，不存在「留顶删底」或「留底删顶」。

统一的实证原因（为什么连根拔掉，而不是只调参数）

  • 在 OOS 样本上 vol_div 对信号质量是净负拖累 ≈ −1.49pp；去掉它后 skill24 从约 −1.49% 升到 +4.26%（当前最优）。
  • 研究曾尝试两种修补，都更差：符号反转(+1.26%) 与 买臂趋势过滤(+0.88%)。
  • 结论：它不是「方向反了」那么简单，而是低信息噪声——最优处置＝禁用，而非调参。

顶背离（卖点）为何不可靠

定义：价格创新高 + 成交量缩量（近段均量 ≤ 前段 ×VOL_SHRINK_RATIO=0.8）。

  • A 股分时里，新高伴随缩量常是「低流动性缓慢推升」或「单笔大买后无量上漂」，随后仍可继续涨——缩量≠动能衰竭。
  • 0.8 阈值对正常量能回落过度触发，生成过早卖信号（卖飞）。

底背离（买点）为何不可靠

定义：价格创新低 + 成交量放量（近段均量 ≥ 前段 ×VOL_EXPAND_RATIO=1.2）。

  • A 股分时里，价跌量增多数不是恐慌见底，而是持续出货 / 机构派发 / 融资盘强平，后面往往继续跌。
  • 它接的是「飞刀」——生成过早买信号（抄底抄在半山腰）。
小结：两个方向都缺乏稳定预测力，且修补无效，故整体禁用。生产因子集仅剩 引力 + MACD 两因子；所谓「三因子完全共振」在当前生产配置下不可能发生。

五、仓位管理 · 白话版（小白也能懂）

  • 把 1 成 理解成「你总钱的 10%」。
  • 引擎每天盯着一只票的分时价，看它偏离均价（VWAP）有多远，再结合一个叫 MACD 的「拐点确认灯」。
  • 每来一个买 / 卖信号，系统按下面规则定「这一笔买 / 卖多少」：
    • 情形一（强信号）：价格已偏离均价 ≥2%，或者 MACD 灯亮了（确认拐点）→ 这一笔建议 4 成（40%）。
    • 情形二（弱信号）：既没偏离那么多（<2%），MACD 灯也没亮 → 这一笔建议 2 成（20%）。
  • 实际跑下来：因为现在每个信号都强制带 MACD 确认，所以平常的信号基本都是 4 成；只有早上开盘前 15 分钟 MACD 还没成型时，信号才是 2 成。
  • 能买多少有天花板：同一只票，不管来几个信号、怎么加，当天最多堆到 8 成（80%），绝不满仓（留 2 成机动）。已经持有 4 成、再来一个 4 成买入 → 只能加到 8 成封顶。
  • 买和卖用同一把尺子（对称）：买 4 成 / 卖 4 成，规则一样。唯一差别：卖空（反 T）遇到涨停板时不开新空（怕被轧空），买没有这个限制。
  • ❗没有「三个指标都亮 → 仓位更大」这种规则。仓位大小只看「偏离远不远 / MACD 灯亮没亮」，不看法有几个指标同时亮；真正的上限是「单票 8 成」。

六、是否另立独立风控 agent？—— 建议方案

推荐：独立风控 agent 更合理。
  • 理由：tpoint 的强项是「个股分时价格结构」做 T；风控是另一套本事（大盘 / 板块 / 持仓集中度 / 涨跌停 / 熔断 / 黑天鹅），tpoint 单票引擎不建模这些——前文已确认它完全不读大盘。
  • 分工：tpoint = 日内差价信号生成 + 执行；风控 agent = 组合层「总闸」，盯大盘与总敞口，触发时通知你并命令 tpoint 清仓。这也让第四节的「清仓」功能有了用武之地。
  • 落地缝（最小改动、解耦清晰）：风控 agent 写控制文件（如 data/risk_command.json 写 {action:"clear_all"}），tpoint 每轮扫描读取 → 执行清仓。
  • 折中（若想先轻量）：先在 tpoint 内复活 exp/index-gating 的 5m 指数门控（不另起 agent），但长期仍推荐独立 agent 可扩展。
