# tpoint 定位校正与核心竞争力体系

> **文档日期**：2026-08-01
> **背景**：此前以卡方 T0 系统为参照（60% 胜率 / 1.6 盈亏比 / 5002 只全市场筛选 / 程序化执行）衡量 tpoint，
> 结论 8/8 未达标。经用户定位澄清，确认 **tpoint 与卡方不是同一个物种**，KPI 体系需整体校正。
> 本文档为 tpoint 长期定位与考核基准的**权威真源**。

---

## 一、定位声明（一句话）

**tpoint = 个人持仓做 T 的"哨兵工具"**：对用户自选标的（T+0 的 ETF/LOF + 持有个股）做分钟级信号监控与飞书推送，
帮用户降低持仓成本、增厚底仓收益。**不选标的、不自动下单、不承诺策略收益**。

## 二、tpoint 与卡方系统的本质差异

| 维度 | 卡方 T0（机构系统） | tpoint（个人哨兵） |
|---|---|---|
| **定位** | B 端金融科技服务，卖 T0 算法工具 | 个人持仓做 T 的信号推送工具 |
| **标的** | 全市场 5002 只 → 三条件筛选 40 只 | 用户手工维护 watchlist（4~6 只持仓/观察） |
| **执行** | 程序化毫秒级拆单，滑点≈0 | 飞书信号推送 + 人工执行 |
| **盈利来源** | 算法服务费 + 超额收益分成 | 降成本 / 增厚用户底仓收益 |
| **开仓** | 开仓率 12.22%，不强行交易 | 信号触发即推（需引入开仓纪律） |
| **考核** | 年化/夏普/回撤/开仓率 | **信号质量 + 推送可靠性 + 开仓纪律** |
| **护城河** | 标的筛选能力 + 程序化执行 | **见下文三大核心竞争力** |

**一句话**：卡方是"选标的的系统"，tpoint 是"盯持仓的哨兵"——前者优势在事前筛选，后者价值在实时监控+可靠送达。

## 三、tpoint 的三大核心竞争力（KPI 体系）

> **这几个才是 tpoint 的核心竞争力**（用户 2026-08-01 确认）。

### KPI-1：信号质量（能赚钱的信号占比）
- **定义**：推送的 B/S 信号，按用户实际费率（万一佣金不免五 + 印花万5.641(个股) + 滑点）扣成本后净收益 > 0 的比例。
- **当前口径**：`core/exit_manager.py` `simulate_day`（净收益）+ `aggregate_metrics`（净胜率/毛胜率对照）。
- **参考线**：**不套用卡方 60%**。tpoint 是持仓标的做 T，胜率目标结合开仓纪律后按实盘复盘滚动校准
  （初始参考：净胜率 ≥ 50% 为合格，≥ 55% 为良好，逐步向 60% 收敛但**不以达标为门槛**）。
- **配套指标**：盈亏比（≥1.2 合格）、均盈/均亏、毛-净胜率差（成本侵蚀监控）、年化/回撤（参考）。

### KPI-2：推送可靠性（不丢推、可补发）——当前最强项
- **定义**：信号从"引擎触发 → 飞书送达"全链路不丢失、可审计、可补发。
- **现有机制**（生产已具备）：
  - `push_audit.jsonl` 投递审计（每推必记）
  - `push_pending.jsonl` 补发队列（`REPLAY_MAX_AGE_S=600` 新鲜度闸门，跨重启过期失败推送直接丢弃）
  - `state.json` 实盘计数（`_b_count_{sym}_{YYYYMMDD}` / `_s_count_*`）权威源
  - 首扫抑制（重建持仓状态、抑制历史信号重放）+ 补发闸门（防 07-30 重放风暴复发）
- **考核**：丢推率 = 引擎触发未送达 / 引擎触发总数，目标 **0**；送达延迟目标 < 5s；审计可追溯 100%。

### KPI-3：开仓纪律（少推、推准，不强行交易）——借鉴卡方最有价值的一点
- **背景**：卡方开仓率仅 12.22% = 88% 时间不开仓，只在"高波/高换手/高振幅"确定性环境出手（PPT S6 实证）。
- **tpoint 落地方向**（不预测"单边下跌日"，用纪律规避）：
  - 低波/低换手/低振幅市况 → **降频推送甚至静默**，只保留高置信信号
  - 单边下跌/上涨趋势 → 减少均值回归类信号（floor 抄底）触发
  - **严禁用"收盘<开盘"等日级事后标签过滤盘中信号**（前视偏差，2026-08-01 实验证伪：盘中可判定等价物全部无效）
- **考核**：信号密度（每日每标的信号数）有上限；无效信号率（推送后未达净收益的信号占比）持续下降。

## 四、与卡方的关系：借鉴什么、不追什么

| 卡方能力 | tpoint 态度 | 理由 |
|---|---|---|
| 标的筛选（5002→40） | **暂不追**（除非用户改变定位） | tpoint 定位=盯持仓，不选标的；若未来扩大池子需先有回测验证筛选器（用户 2026-07-31 决策） |
| 程序化执行 | **不追**（用户已拍板保持人工） | 需券商 API + 风控前置，超出哨兵工具定位 |
| 开仓纪律（12.22%） | **借鉴核心** | 直接提升信号质量的杠杆，且无需新能力 |
| 绩效统计体系（17列） | **参考** | 开仓率/滚动窗口等可复用，但考核权重归位 KPI-1/2/3 |
| 信号算法（5因子黑盒） | **不追** | 内核不透明无法验证，tpoint 用自研 miji 引擎（gravity+MACD背离+floor门控） |

## 五、定位校正后的工作优先级（替代"对标卡方达标线"）

1. **P0-信号质量**：开仓纪律落地（少推、推准）+ 日级趋势状态过滤的盘中可判定替代方案研究
2. **P0-推送可靠性**：维持现有 0 丢推，持续监控补发队列与审计
3. **P1-复盘口径**：每日复盘按新 KPI（信号质量/推送可靠性/开仓纪律）出报告，逐步替代"卡方对标"口径
4. **P2-候选池**：仅当用户想扩 watchlist 时，才用 backtest_screener 验证（达标才并入），不作常态任务

## 六、历史结论的重新解读（避免误导）

- **"8/8 未达标"（2026-08-01 回测）**：是"卡方 60% 胜率/1.6 盈亏比"尺子下的结论。按新定位，tpoint 的正确考核是
  "持仓标的中哪些日子适合做 T、信号能否净赚"，而不是"标的能否达到机构级筛选线"。
- **"日级趋势闸门证伪"（2026-08-01）**：盘中可判定闸门（VWAP/趋势强度）实验全部无效 → 佐证开仓纪律应走
  "环境降频"路线而非"信号过滤"路线。
- **"卡方胜率中位 61%"**：那是 5002 只里筛出 40 只后的结果，不代表"任何标的做 T 都有 61% 胜率"。
  tpoint 若盯的是持仓标的，标的质量由用户负责，系统负责的是"这个标的今天的信号靠不靠谱、推得准不准"。
