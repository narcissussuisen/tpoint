🔍 分时图 vs 回测报告 差异排查报告

排查时间：2026-08-02 21:00 · 标的：161129.SZ 原油LOF · 数据：F盘 tickflow 1m 缓存（07-24）· 生产版本：v9.3.0

一、问题概述

用户反馈：最近生成的分时图（signal_chart）与之前回测报告中的结果差异极大，分时图效果明显差于回测数据。
排查结论：这不是单一 bug，而是「双引擎漂移」——生产引擎与隔离回测引擎的参数与功能已经分叉。同一份行情数据，两个引擎输出的信号数量与买卖点完全不同。

三、根本原因

核心结论：tpoint 存在两套并行的信号引擎，参数与功能已漂移分叉：

1. core/miji_alpha.py（v9.3.0 生产引擎，分时图 / monitor / daily_signal_review / backtest_screener / backtest_visualize 共用） —— 已落地 P0（MHD=0.15）、P1（ATR 0.25 per-symbol）、P3-1（mpr_b60 per-symbol）、P2（VWAP_DEV_BUY=0.65）、高波动守卫 ×1.5。
2. backtest/keyfactor/miji_engine.py（07-22 之前建立的隔离研究引擎） —— 参数停留在 v9.2.2 之前：VWAP_DEV_BUY=0.6、无 MHD 阈值、无 ATR/mpr per-symbol、无高波动守卫。 至今仍被旧复盘/诊断脚本引用（compare_strict_floor_symbol.py / early_session_0722_review.py / exec_compare_0721.py / floor_signals_today.py / _probe_pairing.py）。

用户此前看过的"回测报告"若由这些旧脚本生成，其信号量天然比 v9.3.0 生产口径多（弱背离 + 无 mpr 拦截）， 造成"分时图明显差于回测"的观感。这不是算法灵敏度问题，而是版本口径不一致。

附带发现 miji_engine.py L520 有 bug：details.append(f'MACD{m_detail}') 应为 parts.append(...) （在 check_miji_trigger 内，变量名错误，仅在 S 信号含 MACD 因子时抛 NameError）。

四、修复方案

优先级修复项具体操作
P0统一 PC 取法signal_chart.py plot_one() 改为从前一日收盘取 PC（复用 daily_signal_review.get_pc 或 backtest day_prev_close 逻辑），消除跳空日 floor 门控偏差
P0废弃/归档旧引擎 miji_engine.py把引用它的旧脚本（compare_strict_floor_symbol / early_session_0722_review / exec_compare_0721 / floor_signals_today / _probe_pairing）迁移到 miji_alpha，或明确标记"研究历史版不参与生产对比"；防止继续产生误导性回测报告
P1修复 miji_engine L520 bugdetails.append → parts.append（若保留该文件）
P1建立"单引擎"约束在 docs/versioning.md 中写明：所有信号复算/回测/复盘必须 import core.miji_alpha（v9.3.0 生产同源）；backtest/keyfactor/miji_engine.py 仅作历史研究存档，不再用于新报告
P2报告标注引擎版本backtest_visualize / daily_signal_review / signal_chart 输出 JSON/HTML 时追加 engine_version: v9.3.0 字段，避免未来再混淆
建议验证路径：修复 PC 取法后，重跑 signal_chart 与 daily_signal_review 对比 161129 07-24/07-20， 二者信号应完全一致（除反T回补 X 在 simulate_day 不记账外）。
