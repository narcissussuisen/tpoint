🛠️ tpoint 进程重启教程

核心思想：只杀 python 进程，不杀 bat 窗口 — 守护脚本 run_*.bat 的 :loop 会在 5~30 秒内自动用最新磁盘代码重拉。永远不必重启电脑。

📐 原理（先看一眼，少走弯路）

  • 登录自启 V9Launch.bat 用 start /MIN cmd /c run_monitor.bat 拉起一个叫 v9_monitor 的最小化窗口。
  • run_monitor.bat 里有 :loop：每 30s 检查 data/.monitor.pid 对应的进程是否还活着（且命令行含 monitor.py）。活着就跳过，死了就重拉。
  • 所以你只要让 monitor.py 那个 python 进程死掉，父 bat 检测到后会自动重启它 —— 新代码就这么加载了。
  • 类比 这跟 Linux 的 systemd restart 一个道理，只是用 bat 的 :loop 当守护进程。

最推荐 方法一：用 .monitor.pid 杀（最稳，不踩权限坑）

monitor 启动时把 PID 写进 data/.monitor.pid。直接读出来 Stop-Process。这条路完全不依赖 CommandLine 可见性，所以没有 WMI 权限坑。

# 一行搞定
Stop-Process -Id (Get-Content "C:\Users\YZP\WorkBuddy\Claw\tpoint\data\.monitor.pid") -Force

或更直白的三步版（先看进程再杀，适合多 python 进程场景）：

# 1) 先看 python 进程（带启动时间，方便辨认哪个是 monitor）
Get-Process python -ErrorAction SilentlyContinue | Format-Table Id, ProcessName, StartTime -AutoSize

# 2) 读 PID 文件、杀
$pid = Get-Content "C:\Users\YZP\WorkBuddy\Claw\tpoint\data\.monitor.pid"
Stop-Process -Id $pid -Force

备选 方法二：按命令行匹配（需管理员）

如果 PID 文件丢失/损坏，可按命令行匹配。但 Win10/11 默认非管理员会话下 Win32_Process.CommandLine 返回 NULL，会导致静默不过滤。必须右键 → "以管理员身份运行" PowerShell才靠谱。

Get-CimInstance Win32_Process -Filter "Name='python.exe'" | `
  Where-Object { $_.CommandLine -like '*monitor.py*' } | `
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }

否则你会看到"啥也没发生、也没报错"——这就是 CommandLine 被 NULL 过滤掉的征兆，改回方法一即可。

✅ 验证是否复活（30 秒后做）

1
PID 变成新数字：type "C:\Users\YZP\WorkBuddy\Claw\tpoint\data\.monitor.pid"
2
控制台出现新启动标记：
powershell -Command "Get-Content 'C:\Users\YZP\WorkBuddy\Claw\tpoint\logs\monitor_console.log' -Tail 6"
应看到 v9 启动 / 预热成功（数据源连通） 之类的新时间戳行。
3
或直接查进程在不在：
Get-CimInstance Win32_Process -Filter "Name='python.exe'" | ?{$_.CommandLine -like '*monitor.py*'} | select ProcessId,CommandLine

🔁 兄弟进程（engine / selfcheck / vr_risk）同理

它们各自由 run_engine.bat 等守护，都有 :loop，杀对应 python 进程即可自动重拉：

# 重启 alert_engine（推送引擎）
Get-CimInstance Win32_Process -Filter "Name='python.exe'" | ?{$_.CommandLine -like '*alert_engine.py*'} | %{Stop-Process -Id $_.ProcessId -Force}

# 重启 selfcheck（盘前自检）
Get-CimInstance Win32_Process -Filter "Name='python.exe'" | ?{$_.CommandLine -like '*selfcheck*'} | %{Stop-Process -Id $_.ProcessId -Force}

提示 你这次的改动全在 monitor.py，通常只需杀 monitor；只有改了出场推送相关（emit 等也同在 monitor.py）也只杀 monitor。engine 一般不需要动。

千万别做 三件事

  • ✗ taskkill /T 树杀：会把 run_monitor.bat 那个 cmd 窗口一起杀掉，:loop 没了 → 没人重拉 → 真空，只能登出重登或重启。
  • ✗ 手动关闭 "v9_monitor" 最小化窗口：那正是 :loop 宿主，关了同上，失去自动重启能力。
  • ✗ 为了加载新代码而重启电脑：完全没必要，按上面杀进程 30 秒搞定，比重启快一个数量级。

💡 常见问题

  • 杀完多久复活？ monitor ≈30s（run_monitor.bat 的 timeout /t 30），engine ≈5s。想更快可改对应 bat 里的秒数（可选）。
  • 新代码一定能加载吗？ 能。重拉是重新 python core\monitor.py，从磁盘重新 import，所以你改完存盘后杀进程即生效。
  • 杀完会丢信号吗？ 仅重启那 30s 窗口内不产生新信号；进程起来后下一轮立即补刷 PC 并恢复。属于预期内的短暂空窗，不是故障。
  • PID 文件是旧的怎么办？ 不用管。run_monitor.bat 会同时用 Get-CimInstance 校验命令行，PID 失效/复用都会判定为"已死"而重拉。
  • WorkBuddy 里能远程杀吗？ 不能。monitor 是宿主机会话（Session 0）进程，需在宿主机本地 PowerShell/CMD 执行上面的命令。
  • 方法二命令贴上去"啥也没发生"？ 八成是 Win32_Process.CommandLine 返回 NULL 的权限坑。改用方法一（PID 文件），或者用"以管理员身份运行"打开 PowerShell 再贴方法二。

⚡ 一句话速记

改完代码 → 打开 PowerShell → 粘贴方法一那条命令 → 等 30 秒 → 看控制台"预热成功" → 完事。 比重启电脑省 2 分钟。
