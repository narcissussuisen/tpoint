tpoint v9.3.0 · 排查日期 2026-08-02 · 依据：output/t0_optimization_research_2026-08-01.html + 生产代码实证
一句话结论：两套结果不是同一套系统——ML 研究报告度量的是「信号点 + 固定持有 20 根 1m bar」的静态前向收益，而生产 v9.3.0 度量的是「信号 + 移动止损/反向信号出场管理」的动态 round-trip；且 ML 训练时用的是无过滤基线（mhd=0.0、无 per-symbol ATR/MPR），生产实盘却已叠加 mhd=0.15 + atr0.25 + mpr_b60 三道过滤。差异是结构性、系统性的，不是参数微调能弥合的。

🎯 根因判定

⚠️
最可能导致不匹配的环节（按影响排序）：
  1. 维度三——训练样本与生产信号的系统性差异（根因）：ML 在无过滤基线（mhd=0、无 ATR/MPR）上训练，生产已叠加 3 道过滤。实验证明 161129 07-24 上 ML 基线 5 信号、生产只剩 1 个，3 个 B 信号全部被过滤 → 模型学到的最优因子基于的是生产永远不会看到的样本。
  2. 维度四——收益口径错配：固定持有 20 根 vs 出场管理 round-trip，两种完全不同的「胜率」定义。
  3. 维度一——因子空间错位：ML 的 top 特征（is_morning 31.4%、KDJ、多周期 MACD）在生产中不存在或约等于无。
  4. 维度五——产物无落地：ml_rules.json 从未被生产引用，推荐参数（mhd=0.15 是唯一已落地的）与生产手写阈值无关联。

✅ 验证修复后与 ML 结果趋于一致的方法

思路：让 ML 训练数据对齐生产信号链，再对比模型是否还能学到「最优因子」。
  1. 对齐信号层（首要）：在 ml_build_dataset.py 的 detect_miji_signals 调用中注入生产链参数： 
    sigs = detect_miji_signals(data, pc, enable=(True, False, True),
                           macd_gate_mode='floor',
                           macd_min_hist_diff=0.15,     # ← P0 生产值
                           atr_min_pct=0.25,            # ← per-symbol（按标的查 monitor_config.json）
                           mpr_enable='B', mpr_periods=[60])  # ← per-symbol
    或直接用 detect_for 裸信号层替代（不经出场状态机，只取 B/S 候选），保证训练样本 = 生产候选信号集。
  2. 对齐收益口径：label 改用「生产出场管理 simulate_day 的 round-trip 净收益」而非固定 N 根；若保留固定 N 根，则报告必须明确标注「静态口径」与生产不可比。
  3. 重训并对比：重训后若模型仍能学到 is_morning/KDJ 等强特征 → 说明因子本身有信息量，值得补进生产；若特征重要性塌陷 → 说明原报告的最优因子是「无过滤样本」上的伪优势。
  4. 验收标准：重训模型的 OOS AUC 应重新评估；新规则落地前必须走 backtest_screener.py 固定全集口径验证（≥50% 合格 / ≥55% 良好），且与旧引擎数值差 < 2pp 才算口径对齐。

📋 已确认的代码事实（本轮 grep 实证）

  • core/miji_alpha.py 无任何 KDJ 字段（grep 零命中）→ ML 的 kdj_k/d/j 因子在生产不可用。
  • core/miji_alpha.py L571 注释自证「研究态 mhd=0 vs 生产 0.15」分叉。
  • core/monitor.py 无任何 ml_rules 引用 → 报告推荐参数从未进生产。
  • ml_to_rules.py 推荐 12 条中，仅 min_hist_diff=0.15 与生产一致（且生产实现是独立手工落地）；其余 VWAP_DEV/RSI/KDJ/tail_gate 全部未落地。
  • ML 成本模型与生产同源（cost_for_symbol / make_cost_model）→ 维度四的成本项一致，可排除成本差异因素。
  • ml_build_dataset.py L26 设置 os.environ['MACD_GATE_MODE']='floor' → 与生产 floor 门控模式一致。
